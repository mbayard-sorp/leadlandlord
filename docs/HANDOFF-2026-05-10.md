### Content pipeline hardening (ADR 0001)

Triggered by a real production cascade ("roof replacement / Owensboro KY") that flaked on Attempt 1, "succeeded" on Attempt 2 by gaming the cluster-coverage check. Three changes:

- **`keyword-planner` dedup**: `deduplicateClusters()` runs pre-persist. Groups by `page_kind`, computes a 3-token topic fingerprint (stop words + city/state tokens stripped), drops lower-volume duplicates within a group. Conservative — won't catch semantic redundancy with diverse leading tokens.
- **`content-engine` kind-aware coverage**: `checkClusterCoverage` returns `{covered, missing, kindDrift}`. Two-level salvage gate replaces flat `missRate > 0.2`:
  - Outer guard: `missRate >= 20%` → hard fail (unchanged)
  - Level 1: missing `home`/`service`/`service_area` cluster → hard fail regardless of miss rate
  - Level 2: missing or kind-drifted `info`/`blog` with `missRate < 20%` → salvage + emit `site.build.degraded` event
- **`content-engine/system.md`**: appended "Critical: cluster_key matching" rules.
- HTTP 529 already falls through to retryable `runtime_error` — no edit needed in `error-classify.ts`.

ADR at `docs/adr/0001-content-pipeline-hardening.md`. Architect's bar: **first-attempt success >90%, per-site cost <$0.65, no operator babysitting.**

## Setup notes (learned the hard way this session)

- **Worktree `.env.local`:** the symlink approach (`ln -s /Users/mikebayard/Claude/LeadLandlord/.env.local .env.local`) works for scripts that use `findEnvFile` walk-up. **But:** the dev server must be restarted *after* the symlink is created to pick up new env (it inherits at process start).
- **Local agent processing:** there's no local cron tick. The operator app exposes `GET /api/cron/operator-tick` but no scheduler hits it locally. Production Vercel cron processes queued events every minute against the shared Neon DB — so any local enqueue gets processed by **prod**, which may be missing env (see Namecheap). For local-only event processing, manually `curl http://localhost:<port>/api/cron/operator-tick`. Consider adding a dev-mode interval timer in `instrumentation.ts` so this isn't a surprise next time.
- **DB migrations:** Drizzle's neon-http migrator orders by `when` timestamp in `_journal.json`, NOT by `idx`. Auto-generated timestamps from `drizzle-kit generate` use the file's mtime, so a hand-bumped migration with an older mtime gets silently skipped. Always verify the generated `when` is strictly greater than the latest applied `when` in `drizzle.__drizzle_migrations`.
- **Preview server port:** Vercel CLI default 3000 was in use, so dev server bound to autoPort (`56236` last session). Check `launch.json` config; UI URLs change between restarts.
