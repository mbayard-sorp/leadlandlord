## Vercel alias drift — confirmed and worked around

Yesterday's "deploy mystery" turned out to be: `vercel deploy --prod --yes --force` builds and promotes a deployment to the production target, but does NOT update the canonical custom alias `leadlandlord-operator.vercel.app`. That alias was stuck on a stale deployment.

**Workaround used today:** after every `vercel deploy --prod --yes --force`, immediately run:
```bash
vercel alias set <new-deployment-url> leadlandlord-operator.vercel.app
```

**Permanent fix (followup):** add an `--alias` flag to a deploy script wrapper, OR fix the Vercel project's domain config so `leadlandlord-operator.vercel.app` is bound to "production" properly (currently bound to a specific deployment ID). Not investigated yet.

## DataForSEO cache — how it works

Table: `dataforseo_cache(endpoint, key, payload, fetched_at, expires_at, cost_usd, hit_count, last_hit_at)`. Unique on `(endpoint, key)`.

Wrapped functions in [packages/integrations/src/dataforseo/index.ts](packages/integrations/src/dataforseo/index.ts):

- `getKeywordCandidates({seed})`:
  - key = `${language}:${seed}:r${relatedLimit}:s${suggestionLimit}`
  - TTL: 90 days
  - Cost: ~$0.028 per fetch
  - **Cross-city win**: keyword-planner emits 5 seeds per build. 4 are city-independent (`<niche>`, `<niche> near me`, `<niche> cost`, `<niche> services`). Only `<niche> <city>` is city-specific. So building a second site in the same niche pays for 1 of 5 seeds = **80% reduction**.

- `getLocalKeywordMetrics({keywords, location})`:
  - key = `sha256(language|location|sortedKeywords)`
  - TTL: 30 days
  - Cost: ~$0.0016 per keyword

`MOCK_AI=true` bypasses the cache entirely (mock data is free; don't pollute the cache).

`forceRefresh: true` option on both for explicit re-fetches.

## Two real bugs fixed by stepping through

### 1. `'info'` missing from `PageKind` enum

**Symptom:** Mock build failed at content stage with `Invalid enum value. Expected 'home'|'service'|...|'blog', received 'info'`.

**Cause:** Recent `info_pages` feature added a Page array but didn't extend `PageKind`. `persist-sanity.ts:108` had a `'info' as PageKind` cast that hid the gap from TypeScript. Sanity schema already accepted 'info'.

**Fix:** Added `'info'` to [packages/shared/src/types.ts:10](packages/shared/src/types.ts:10) and to the system prompt at [packages/agents/src/content-engine/system.md:115](packages/agents/src/content-engine/system.md:115).

### 2. Stale Sanity clusters on the water-softener test site

**Symptom:** First mock retry of water-softener / Peoria failed at content stage: `cluster coverage too low: 271/277 clusters not covered`.

**Cause:** Same `(niche, city, state)` upserts to the same `site_id`. `loadKeywordClustersForSite()` reads ALL non-retired clusters for that site_id from Sanity. Yesterday's incident left 277 stale cluster docs there. New keyword-planner run added 6 more, but content-engine only covered the 6 it knew about → 271 missing → coverage check failed.

**Fix:** Bulk-deleted 277 stale clusters from Sanity (transaction `ceMhUzV0M6UiosSOPSAX8u`). Used a fresh niche/city for the actual test.
